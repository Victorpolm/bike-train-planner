# Re.route licensing status

_Reviewed 11 October 2026._

The repository is publicly visible. The owner has not yet chosen a project-wide software licence. This document does not grant a new licence to the original Re.route code, change third-party rights, or claim legal clearance. GitHub's platform terms and applicable law still apply. `prototype-v0/package.json` being marked private is an npm publication setting, not repository access control.

Before intentionally offering reuse, the owner should choose whether to retain a proprietary project, offer a permissive open-source licence (for example MIT), or require source sharing under an appropriate copyleft licence. These have different consequences; no option has been selected on the owner's behalf. Preserve ownership and any contributor rights when making that decision.

Independent components retain their existing licences. Full production dependency notices are in [third-party-notices.txt](prototype-v0/public/third-party-notices.txt), with [versioned inventory](prototype-v0/public/third-party-dependencies.json). The application build checks that these match installed dependencies. These notices are also served inside the app.

Datasets and service access have separate terms; a software licence cannot relicense someone else's geodata, photos, API or marks. See the [source register](docs/DATA_SOURCE_REGISTER.md) and [launch review](docs/OFFICIAL_CYCLING_AND_LAUNCH_REVIEW_2026-10-11.md). In particular, preserve OSM attribution and applicable ODbL obligations, swisstopo/SwitzerlandMobility attribution, and source-specific restrictions. Restricted facility integrations are disabled.

The Re.route name is not cleared for trademark use. Similar navigation/planning names were identified; professional searches and advice remain pending. No patent freedom-to-operate determination is made.
