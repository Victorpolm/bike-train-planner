# User research

## Goal

Determine whether bike + public-transport planning is a recurrent enough problem to justify a dedicated product, and identify which parts of the journey actually create friction.

## Interview approach

Prefer concrete past behavior over hypothetical enthusiasm.

Good opening:

> Tell me about the last time you travelled somewhere by bicycle and train.

Follow with:

- What was the origin and destination?
- Which apps/sites did you use?
- How did you choose the departure station?
- Did bicycle carriage rules matter?
- Did you need a reservation?
- Did station access matter?
- Did you reject a route because of unpleasant roads?
- What information was missing?
- What went wrong?
- Would you plan the same trip differently next time?

Avoid relying on “Would you use this app?”

## User groups to include

- commuters
- recreational cyclists
- cycle tourists
- e-bike users
- weekend bike + train travellers
- cargo-bike users
- parents with trailers
- cyclists who strongly avoid traffic

## Initial validation heuristics

- 15–20 interviews
- ~10 with a recent relevant problem
- ~5 already combining multiple tools
- ~5 willing to test a prototype

These are practical thresholds, not statistical proof.

## Prototype tasks

When testing a prototype, ask users to:

- plan a real commute or leisure trip
- compare several journey alternatives
- identify whether a bicycle reservation is required
- choose between faster and more comfortable cycling access
- report confusing or incorrect information

## Metrics

High-value signals:

- successful journey planning
- route chosen
- whether the recommendation would actually be used
- repeat use
- reduction in number of apps/sites needed
- route changes due to bicycle-specific information
- incorrect-data reports

Low-value vanity signals:

- compliments
- downloads
- map views
- time spent in app

## Interview record template

### Participant
Anonymous ID / segment only.

### Journey
Origin, destination, purpose, date/frequency.

### Current workflow
Tools used and sequence.

### Friction
Specific problems encountered.

### Bicycle constraints
Carriage, reservation, station access, route comfort.

### Workaround
How they solved the problem.

### Product implication
What this suggests, without overgeneralizing.

### Evidence strength
Single anecdote / repeated pattern / contradicted by others.
